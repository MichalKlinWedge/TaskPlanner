## Project

Task Planner: personal daily task manager. Web app (`apps/web`, Next.js 16, PWA) for planning: kanban, calendar with time-blocking, timeline/Gantt, weekly review. Android app (`apps/mobile`, Expo SDK 58) for capture and execution: quick add, Today, reminders, focus mode, habits, widgets. **Both clients are local-first and edit everything offline.** Backend: Supabase (Postgres + RLS + Realtime + Storage + Edge Functions + `pg_cron`), web on Vercel. Same stack and conventions as ExpeditionPlan (`D:\AI\ExpeditionPlan`), which is the reference for patterns.

## Architecture rules

- **UI reads and writes only the local database** (expo-sqlite on the phone, `@sqlite.org/sqlite-wasm` with `opfs-sahpool` in a web worker, one leader tab). Network is `packages/sync`'s job in the background — no separate „offline path” in UI code.
- **Domain logic lives in `packages/core`**: pure TS that runs identically in the browser, on the phone (Hermes) and in Supabase Edge Functions (Deno). No Node/Expo/Next imports outside tests. Quick-add parser, recurrence, views (Today/Upcoming/grouping/filters), dependencies, time-blocking, habits, reminders, Pomodoro, review queue all go here.
- Packages are consumed as **TypeScript source** (`main: src/index.ts`) with **explicit `.ts` extensions in relative imports** (Deno). Next transpiles them via `transpilePackages`.
- **Zod schemas are the single source of truth** (`packages/core/src/schemas`) for forms, `jsonb` columns and RPC payloads. jsonb is camelCase, columns snake_case.
- **Labels and formatting** live in `packages/core/src/labels.ts` (`PRIORITY`, `TASK_STATUS`, `LIST_KIND`, `PROJECT_STATUS`) and `format.ts` (`plural`, `pluralForm`, `formatMinutes`, `dayLabel`, `dayChip`, `dayMonth`, `shortDate`, `capitalized`); apps never redefine them.
- **Task time is floating** (local wall clock): `due_date` (`RRRR-MM-DD`), `due_time` (`GG:MM`), `duration_min`, optional `start_date`; optional `time_zone` pins a task to a zone. Real events (completions, time entries, calendar events) are `timestamptz`.
- Manual order = fractional `sort_key` (`core/sort-key.ts`, from ExpeditionPlan).
- **Sync (SPECYFIKACJA §6, `supabase/migrations/*_poc1_sync.sql`, `docs/POC_WYNIKI.md`)**: scope = workspace (`scope_id` = workspace id, no `workspace_id` column) or the user's personal scope (id = user id, created by a trigger on `auth.users`); membership in `scope_members`. `scope_id` of tasks/task_tags/task_completions is **derived** server-side (from list/task) and never sent by clients; a subtask's `list_id` follows its parent. `packages/sync/src/specs.ts` (`TABLES`) is the only table ↔ local-row mapping — a new column goes into the migration, `npm run gen --workspace packages/db`, then `TABLES` (tsc fails on uncovered columns), the row schema in `MODEL` (`packages/core/src/schemas/model.ts`; a sync test fails if its keys differ from `TABLES` + `id`) and `synced_tables()`. Every synced row has `scope_id`, `row_version` (trigger bumps `sync_scopes.sync_version` under the scope row lock), `field_clock jsonb` (HLC per field) and `deleted_at` (no hard deletes). Clients write through `mutate` (or `mutateMany` — several ops in one transaction with one view refresh; web `run(ops)` always uses it) → local row + outbox in one transaction; server RPC `push_changes` applies a field only if the op's HLC is newer (idempotent, order-independent) and rejects ops that break rules (subtask depth > 4, parent cycles, cross-workspace refs). `pull_changes` returns rows with `row_version` above the client's per-scope versions in one snapshot. Realtime on `sync_scopes` is only a signal to pull. `watch` listeners (engine and `TabStore`) get `TableChanges` (table → changed ids, `null` = unknown / > 1 000; `changes.ts`); view tasks come from `createTaskCache` (`task-cache.ts`, also `TASK_COLUMNS`): full read once, then only changed tasks/tags, unchanged `TaskEntry` objects stay identical so apps keep their `ViewTask` in a `WeakMap` — never re-query all tasks on change. Completions/time entries are append-only with deterministic UUIDv5 ids where two devices may write „the same” row.
- Rejection codes from `push_changes`: `TP001` depth, `TP002` cycle, `TP003` no access, `TP004` wrong scope, `TP005` unknown table/field, `TP006` bad HLC. Rejected and clamped ops come back with the server's current row, which overwrites the local one.
- **Browser**: `connectTabs` (`packages/sync/src/tabs.ts`) — the leader tab (Web Locks) owns the SQLite worker and the `SyncEngine`; other tabs proxy queries/mutations over BroadcastChannel. SQLite WASM is **not bundled** (Turbopack can't resolve its dynamic worker URL): `scripts/copy-sqlite-wasm.mjs` (web `predev`/`prebuild`) copies it to `apps/web/public/sqlite-wasm/` (git-ignored), and `apps/web/src/lib/db.worker.ts` loads it with `import(/* turbopackIgnore: true */ …)`. `/dev/sync` is a dev-only test page. Tab messages carry `TAB_PROTOCOL` (`tabs.ts`) — **bump it when adding a tab operation or a local column/table an older leader lacks**; a follower behind an older leader (a tab opened before a deploy) gets `staleLeader` (banner in `signed-in.tsx`) and `mutateMany` rejects instead of silently dropping writes.
- **Phone**: `apps/mobile/src/lib/polyfills.ts` must load first (Hermes lacks `crypto.getRandomValues` for UUIDv7 and a full `URL` for supabase-js).
- Synced tables are written **only via `push_changes`** (RLS still on every table); integration tables (`calendar_*`, `inbound_messages`) only by `service_role` in Edge Functions. OAuth tokens in Supabase Vault — never in the browser or APK.
